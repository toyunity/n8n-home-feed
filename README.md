# 네이버 홈판 주제별 인기 게시물 수집 자동화 (n8n + Python + 구글 시트)

재테크, 건강, 육아처럼 **주제별로 네이버 모바일 홈판(홈피드)에 잘 뜨는 게시물을 매일 모아 점수를 매기고 구글 시트에 정리**하는 자동화 예제입니다.
n8n이 일정·흐름·오류 알림을 맡고, 수집(Playwright)·점수 계산·시트 기록(gspread)은 파이썬이 맡습니다.

> 기본 실행은 **가상 샘플 데이터**(`collector/sample/`, 제목 앞에 `[샘플]`)로 동작합니다.
> 실제 수집은 `LIVE_MODE=1`로 직접 켠 경우에만 동작합니다. 아래 [한계](#한계)를 먼저 읽어 주세요.

## 구조

```
[구글 시트 '설정' 탭]  주제 | 판 코드 | 키워드        ← 의뢰인이 고치는 곳
        │
[n8n] 매일 08시 / 수동 실행
   └─ HTTP → [Python] POST /collect   비로그인 브라우저로 주제판을 차례로 열어 게시물 수집 → 날짜별 저장(SQLite)
   └─ 0건 주제가 있나? ── 예 → 실패 처리 ─────────────┐
   └─ 아니오 → POST /publish   점수 계산 → 시트 '결과_날짜' 탭 (시트 미연결 시 CSV)
[n8n] 오류 워크플로 ◀────────────────────────────────┘ 멈춘 단계·메시지를 '로그' 탭에 기록
```

| 파일 | 역할 |
|---|---|
| `workflows/homefeed-main.json` | 메인 워크플로 (일정, 수집 호출, 0건 주제 검사, 기록) |
| `workflows/homefeed-error.json` | 오류 워크플로 (실패 단계·메시지를 로그로) |
| `collector/feed.py` | 주제판 수집(`collect_live`), 저장, 점수 계산(`score`) |
| `collector/sheets.py` | 구글 시트 읽기/쓰기 (설정·결과·로그 탭) |
| `collector/app.py` | n8n이 부르는 HTTP 서버 (표준 라이브러리) |

## 주제 설정

시트 '설정' 탭 (시트 미연결 시 `collector/config/topics.json`):

| 주제 | 판 코드 | 키워드 |
|---|---|---|
| 재테크 | `DATA` | (비움 = 판 전체) |
| 건강 | `HEALTH` | |
| 육아 | `LIVINGHOME,LECTURE,LIVING` | 육아, 아기, 아이랑, 어린이, 유아, 초등, 임신, 출산, 이유식 |

판 코드 (2026-11 기준 모바일 홈 상단 탭): `HOME` 추천 홈피드, `DATA` 경제, `HEALTH` 건강, `LIVINGHOME` 리빙푸드, `LIVING` 여행맛집, `FASHION-BEAUTY` 패션뷰티, `CARGAME` 카·테크, `LECTURE` 지식, `GAMEAPP` 게임, `SPORTS` 스포츠, `ENT` 엔터

## '잘 뜬다'의 기준

하루치만으로는 판단이 어려워 날짜별 스냅샷을 쌓아 비교합니다.

```
점수 = 연속 노출일 × 10 + (31 − 최고 노출 순위) + (좋아요+댓글 증가량) ÷ 10
```

- 노출 순위: 그 주제 안에서 위에서부터의 순서 (광고 제외)
- 좋아요·댓글: 추천 홈피드(`HOME`) 글만 화면에 표시되므로 그 글에만 반영됩니다

## 실행 방법

```bash
cp .env.example .env
docker compose up -d --build
docker compose exec n8n n8n import:workflow --separate --input=/workflows
docker compose exec n8n n8n publish:workflow --id=homefeedMain0001
docker compose exec n8n n8n publish:workflow --id=homefeedError001
docker compose restart n8n
```

http://localhost:5678 에서 워크플로를 열고 '수동 실행'으로 바로 돌려 볼 수 있습니다.

구글 시트 연결: 서비스 계정 키를 `secrets/service-account.json`에 두고, 시트를 서비스 계정 이메일에 편집자로 공유한 뒤 `.env`의 `GOOGLE_SHEET_ID`를 채웁니다.
연결하지 않으면 결과는 `collector/data/결과_날짜.csv`, 실행 기록은 `collector/data/run.log`에 남습니다.

## 자주 바꾸는 곳

| 바꾸고 싶은 것 | 고칠 곳 |
|---|---|
| 주제·판·키워드 | 시트 '설정' 탭 |
| 실행 시각 | n8n '매일 08시' 노드 |
| 샘플 ↔ 실제 수집 | `.env`의 `LIVE_MODE=1`, `COLLECT_MODE=live` |
| 주제당 결과 행 수 | n8n '점수 계산·시트 기록' 노드의 `per_topic` |
| 스크롤 횟수·요청 간격 | `collector/feed.py`의 `collect_live(scrolls, delay_ms)` |
| 화면 구조가 바뀌었을 때 | `collector/feed.py`의 `HOME_JS`, `PANEL_JS` |
| 오류 알림을 슬랙·텔레그램으로 | 오류 워크플로의 '로그 탭에 기록' 뒤에 노드 추가 |

## 막힐 수 있는 부분과 대응

| 문제 | 대응 |
|---|---|
| 홈판이 계정마다 다르게 보임 | 매번 새 브라우저 컨텍스트, 비로그인 기준으로 고정 |
| 화면 구조 변경 | 주제 하나라도 0건이면 실패로 처리해 로그 탭에 기록 |
| 접속 차단 | 스크롤 간격 1.5초, 재시도 최대 2회, 403·429·캡차 감지 시 재시도 없이 중단하고 기록 |
| 시트 API 오류 | 로그는 파일에 먼저 쓰고 시트는 그다음 |

## 한계

| 한계 | 내용 |
|---|---|
| 주제판이 없는 주제 | 홈판에는 육아 같은 전용 판이 없습니다. 여러 판을 묶어 키워드로 거르면 하루 1~3건 수준이고, 제목에 키워드가 들어간 다른 글이 섞일 수 있습니다. 이런 주제는 네이버 검색 API 같은 다른 출처를 함께 쓰는 편이 맞습니다. |
| 반응 수(좋아요·댓글) | 주제판 카드에는 반응 수가 표시되지 않습니다. 주제판 글의 점수는 연속 노출일과 노출 순위로만 매겨집니다. 글마다 들어가 공감 수를 읽으면 요청이 크게 늘어 차단 위험이 커지므로 넣지 않았습니다. |
| 개인화 | 비로그인 기준 화면입니다. 로그인한 사용자가 보는 개인화 홈판과는 다릅니다. |
| 노출 순위의 의미 | 화면에서 위에서부터의 순서이고, 네이버가 공개하는 공식 순위가 아닙니다. |
| 하루 1회 스냅샷 | 하루 중 노출 변화는 반영하지 않습니다. 실행 횟수를 늘리면 차단 위험도 함께 커집니다. |
| 화면 구조 의존 | 네이버 화면의 HTML 구조를 읽기 때문에 구조가 바뀌면 수집이 멈춥니다(0건 알림으로 감지). |
| robots.txt·약관 | 네이버 robots.txt는 메인 주소(`/`) 외 수집을 허용하지 않습니다. 그래서 실제 수집은 기본으로 꺼져 있고, 켜서 쓰는 판단과 책임은 실행하는 쪽에 있습니다. |
